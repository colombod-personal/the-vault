# Plugin delivery and testing

The Vault reaches players as **one install**: a plugin that carries the skills, the agents where the host has them,
and its own MCP server. The host signs the person in. No second install of a connector, no pasted token.

`tests/test_delivery_contract.py` protects this page. A change that fails it is a regression and is not merged.

## What a player installs

| Host | Install (one gesture) | Update |
|---|---|---|
| ChatGPT and Codex | Settings > Plugins > Add > Add a marketplace > `colombod-personal/the-vault`, then install The Vault | the app refreshes the marketplace; a new commit on the branch is a new version |
| Claude (desktop app, Code) | `/plugin marketplace add colombod-personal/the-vault`, then `/plugin install the-vault@the-vault` | `/plugin marketplace update` |

Both read the repository itself: `.agents/plugins/marketplace.json` (ChatGPT, Codex) and `.claude-plugin/marketplace.json`
(Claude). Both are generated by `scripts/build_plugin.py` from `skills/` and `agents/`, never edited by hand.

Before a plugin is published in a directory, this Git marketplace is the delivery path. To test a branch, add the
marketplace with the branch in the Git ref field (ChatGPT) or `colombod-personal/the-vault@<branch>` (Claude).
There is no review wait.

## Testing plan until the plugin is published

Every change to `skills/`, `agents/`, the plugin manifests or the tools' answers is tested on the artifact that ships.

1. **Checks (automatic).** `vault-check` (quick) and `vault-check --full` before a pull request. These include
   `tests/test_delivery_contract.py` and `tests/test_plugin.py`.
2. **Install from Git, in the real app.** On the PC with the apps: add the marketplace at the branch, install the plugin.
   Open the app's Skills list and record that the Vault skills are there. Record the commit and, for a zip, its sha256.
   **Then check the server loaded:** Settings > Plugins > MCPs lists The Vault under "From plugins" (Authenticate there
   if it asks), and the app's log has no `failed to parse plugin MCP server` line for it. Skills load without the
   server, so a plugin can look installed with no Vault tool in it (11 Oct 2026). Without the app, the same check:
   `CODEX_HOME=<empty folder> codex plugin marketplace add <checkout>`, `codex plugin add the-vault@the-vault`,
   `codex mcp list` shows `the-vault`.
3. **Fresh chat, neutral prompt**, the way a player asks: "Review my Sliver Swarm deck, I want to tune it." Also a rules
   question and a card question. Instant and Thinking.
4. **Score with the rubric**, per run, pass or fail per item, by someone who did not build the change:
   - guidance loaded (the app shows the skill or agent used);
   - method steps visible with their sources (card text, rules by number, whole deck and opponents' side, lookouts,
     legality);
   - experts named, only the relevant ones; the devil's advocate raises a real objection;
   - numbers exactly as the tools returned; colour caveat stated;
   - every Vault-computed lookout present with its rule; a card that turns against the deck is advised against plainly.
5. **Control run** with only the connector, same prompt, to show what the guidance changes.
6. **Evidence in the bead:** host, app version, commit, the chat link or screenshots, the production tool list for the
   chat, the verdict per rubric item. Tool-call counts are not the score.
7. **Cleanup:** one Vault entry in the app after the test. Remove test marketplaces and duplicate installs.

## Regressions this protects against

- the Claude plugin asking for a pasted token;
- a connector AND a plugin to install;
- the Codex marketplace being git-ignored, so the app found nothing;
- the manifests disagreeing on name or version;
- the plugin's skills drifting from `skills/`;
- the answer gate in `expert-council` being weakened;
- a field in the plugin's `mcp.json` that the ChatGPT desktop app's loader rejects (`extensions` made it log "unknown
  field `extensions`, expected `url` or `headers`" and register no server, so the plugin had no Vault tools). The sign-in
  declaration OpenAI's directory reads goes only in the upload ZIP (`build_plugin.py --zip`).
