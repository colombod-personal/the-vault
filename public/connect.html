The Vault

Connect your AI assistant

Ask your own assistant about Magic rules, cards and decks, grounded in Scryfall and the official Comprehensive Rules, with every answer showing where it came from. The Vault is free; your assistant uses your own subscription or key. Nothing here is generated by the Vault itself.

Fastest: paste one line

Pick your assistant, copy its line and paste it into a chat (or the terminal session) there. The assistant reads the setup page, does what its app lets it do itself, and tells you the one step it cannot (adding a connector is a Settings screen, for example). It signs in through your browser, never asks for a token in the chat, is read-only unless you say otherwise, checks the connection with whoami and then gives you a short tour of your own collection and decks (the vault_start prompt). Make your assistant use it

An assistant only gives answers from The Vault when it calls The Vault. Claude and ChatGPT show the assistant the names of the Vault's tools, not the instructions that come with them, so a question that does not mention the Vault (“how does trample work against protection?”) can be answered from the assistant's own memory, which can be out of date. Paste this once into a Claude Project's instructions or your preferences, or start a chat with it:

For Magic rules, card text, rulings, decks, prices and my collection, use The Vault's tools before answering, and never quote a rule from memory.

When you see “Used The Vault” in the answer, it came from the tools. If it does not appear, ask again and name the Vault.

2. Developers: Claude Code, Codex, Cursor, VS Code, GitHub Copilot CLI

Each tool below has its own format, so each has its own block. Where the tool offers it you sign in with your Vault account in the browser and no token is involved. Otherwise open Account → Agents & API and create a personal access token (read-only is enough for rules, cards, deck analysis and your collection; it is shown once). The blocks never put the token in a command: it is read from an environment variable or typed into the tool's own prompt.

Claude Code (plugin: skills and tools together)

/plugin marketplace add colombod-personal/the-vault
/plugin install the-vault@the-vault

It asks for the Vault address (the default is this site) and your token once, and stores the token securely.

Any agent that reads skills (Claude Code, Codex, Cursor, Copilot and more): the skills

npx skills add colombod-personal/the-vault

Add --skill rules-judge for one skill, or -g to install for all your projects. Skills tell your assistant how to answer; pair them with the tools below.

The tools (MCP server) in each tool

Claude Code

Add the server for all your projects, then sign in with your Vault account:

claude mcp add --transport http vault --scope user https://mtgvault.cards/api/mcp
claude mcp login vault

Without browser sign-in: create a personal access token (Account → Agents & API; read-only is enough), keep it in an environment variable named VAULT_TOKEN, and put this in the project's .mcp.json (Claude Code fills in the variable):

{
  "mcpServers": {
    "vault": {
      "type": "http",
      "url": "https://mtgvault.cards/api/mcp",
      "headers": {
        "Authorization": "Bearer ${VAULT_TOKEN}"
      }
    }
  }
}

Inside a session, /mcp does the sign-in too. The plugin above asks for the token once and stores it securely. Format from the tool's own documentation (Claude Code: MCP), read 2026-10-07.

Codex (CLI and IDE extension)

Add the server, then sign in with your Vault account:

codex mcp add vault --url https://mtgvault.cards/api/mcp
codex mcp login vault

Or by hand in ~/.codex/config.toml (Codex uses TOML here, not JSON):

[mcp_servers.vault]
url = "https://mtgvault.cards/api/mcp"

Without browser sign-in: create a personal access token (Account → Agents & API; read-only is enough), keep it in an environment variable named VAULT_TOKEN, and name it in the same table:

[mcp_servers.vault]
url = "https://mtgvault.cards/api/mcp"
bearer_token_env_var = "VAULT_TOKEN"

The CLI and the IDE extension share this configuration. Format from the tool's own documentation (Codex: MCP), read 2026-10-07.

Without browser sign-in: create a personal access token (Account → Agents & API); VS Code asks for it once, hides it and stores it:

{
  "inputs": [
    {
      "type": "promptString",
      "id": "vault-token",
      "description": "The Vault personal access token",
      "password": true
    }
  ],
  "servers": {
    "vault": {
      "type": "http",
      "url": "https://mtgvault.cards/api/mcp",
      "headers": {
        "Authorization": "Bearer ${input:vault-token}"
      }
    }
  }
}

The root key is servers here, not mcpServers. Format from the tool's own documentation (VS Code: MCP servers, VS Code: MCP configuration reference), read 2026-10-07.

GitHub Copilot CLI

Add the server:

copilot mcp add --transport http vault https://mtgvault.cards/api/mcp

Or by hand in ~/.copilot/mcp-config.json:

{
  "mcpServers": {
    "vault": {
      "type": "http",
      "url": "https://mtgvault.cards/api/mcp",
      "tools": [
        "*"
      ]
    }
  }
}

Without browser sign-in: create a personal access token (Account → Agents & API). In a Copilot CLI session run /mcp add, choose HTTP, enter the address above and type this into the HTTP Headers prompt (not into a command):

{
  "Authorization": "Bearer vault_pat_..."
}

The Copilot CLI documentation we read describes headers for remote servers and does not describe a browser sign-in, so this block uses the token. Format from the tool's own documentation (GitHub Docs: add MCP servers to Copilot CLI), read 2026-10-07.

3. Check it works

Ask your assistant: “Call the Vault's whoami tool.” It should name you, your scopes and which data versions the Vault holds (the Comprehensive Rules edition, card data and price dates). Then try these five:

  1. “Does Lightning Bolt kill a creature with 3 toughness that has protection from red? Cite the rules.” The assistant looks up the card and the rules, quotes them, and names the rules edition.
  2. “Review my sliver deck with the expert council.” It finds your saved deck, shows its name, format and commander first, then answers as the format expert, the casual table, the judge and a devil's advocate, each citing what the tools returned.
  3. “What am I missing for my sliver deck, and what will it cost?” Your collection against the deck: owned, partly owned and missing cards, with dated Scryfall prices.
  4. “Show me the printings of Sol Ring that I own.” The printings in your collection, with pictures.
  5. “Add a Sol Ring to my collection.” It shows exactly what would change and waits for your yes. You can undo it.

The Vault will not do these, and a good assistant says so: “Which shop is cheapest right now?” (it has no shop prices, only dated Scryfall ones), “Buy me this deck” (it never contacts stores), “Delete my account” (account actions stay with you in the Vault).

Who this is built on

The Vault reads from these services on your behalf and says what it sends to each one (never your name, e-mail or collection). Every answer carries its source.

  • Scryfall: Card data, rulings, images and prices: Scryfall.
  • Scryfall Tagger contributors: Role tags: Scryfall Tagger, by its community of volunteers.
  • Commander Spellbook: Combos: Commander Spellbook and its community.
  • Archidekt: Deck lists: Archidekt, by their authors.
  • Moxfield: Moxfield file format.
  • Dragon Shield (Card Manager): Dragon Shield export format.
  • TCGplayer, Cardmarket and Cardhoarder: Prices: TCGplayer, Cardmarket and Cardhoarder via Scryfall, dated.
  • EDHREC: Popularity rank: EDHREC, via Scryfall.
  • Card illustrators: Illustrated by the credited artist.
  • Google, Microsoft, Apple and Facebook sign-in, and passkeys: Sign-in by the account you already have.
  • Vercel, Neon and GitHub: Hosting and code: Vercel, Neon, GitHub.
  • Open source software: Built on open source: see the credits page.

How each is used, and thanks: the credits page.

What to expect

  • Answers cite rule numbers and the rules edition, and say when the sources do not settle a question.
  • Material from Scryfall and Wizards of the Coast is shown as theirs. Figures the Vault works out (legality, budget, counts) are labelled as computed, with their sources.
  • Prices are Scryfall's, dated, not a store's price today. The Vault never contacts stores or fills carts.
